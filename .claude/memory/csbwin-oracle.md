`bash tools/csbwin-oracle/oracle.sh build` compiles `doc/CSBwin-src/`'s Linux build (SDL2 and GLib headers fetched with `apt-get download`, nothing installed) into `doc/CSBwin-src-oracle/`; `play <run folder> [<from>-<to>]` plays its `playfile.log` unpaced (a run in ~20 s) and prints each "Sequence/timing error" with `d.Time`, and every draw in the hex range with its callers (`draws.txt`, `c++filt`). `--version=11.014` after the command does the same for 11.014's source (32-bit, sdl12-compat), which plays all four 11.0xx runs to their end; it prints `at d.Time` every 0x400 ticks, so its last such line is only the bucket play reached.

**Why:** the port's own `--trace` only shows the port's side; diffing the two draw lists per tick found an F24 drift in minutes after hours of guessing. A drift CSBWin 2023 shares at the same place is the run's version's, not the port's.

**How to apply:** for any F24 drift, or any doubt about what CSBWin draws at a moment, run the oracle before reading code. Add a `TraceLine("…", …)` call (declared in `CSBCode.cpp` by the patch) to a scratch copy for state the draws don't show. A run folder needs its `graphics.dat` and `dungeon.dat` (the collection's, `../DMweb-extra/Clone,CSBwin,Movies,Data/<movie>/<run>/`, not `tools/fixtures/csbwin-runs/`, which holds logs only; copy it to the scratchpad, as its `Playfile.log` is capitalised). For a quick trace, edit the build folder's copy (`doc/CSBwin-src-11.014-oracle/<File>.cpp`), recompile that one object and relink with `oracle.sh`'s own `g++` lines (seconds, not a `build`), and put the original back after. Before suspecting a version's code, print the inputs on both sides: DMMovie42's line-783 drift was the log's `#DMRules`, not 11.014. When the draws agree but a later tick parts, trace every `MoveObject` (11.014's `Code11f52.cpp`) and every timer as `ProcessTimers` takes it, sequence included (raw bytes 10-11), on both sides from `d.Time` 0, and diff: the first line that differs is the cause, possibly a thousand ticks before the drift (DMMovie42's line 7483 was a missile's range at 0x2d0c, shifting the timer sequences). Don't edit `oracle.sh` while a loop runs it (bash reads scripts as it goes), and don't `pkill -f` a pattern your own command line contains. See [[memmove-source-first]] for reading CSBWin itself.

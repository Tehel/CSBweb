# CSBWin DSA Reference (Sourced)

This document captures verified DSA behavior from the CSBWin C++ source under `doc/CSBwin-src/`.

## DSA loading

- `DSA::Read` loads `description[80]`, `state`, `localState`, `groupID`, `numState`, and `firstDisplayedState`, then reads only the non-empty states; `DSAState::Read` enforces `numAction <= 12` (`doc/CSBwin-src/DSA.cpp`).

## Program words and `&` operations

- A command's relative-state field is followed by a 16-bit state word only when `IsMaxState()`, which every command class defines as `nextState == -MAXSTATE` (`doc/CSBwin-src/Data.h:1904-2399`). `QUESTION`'s `MAXSTATE` is 2, so a field of -2 takes the word. Every other `MAXSTATE` is the field's most negative value (-8, -32, -16, -512, -4), whose negation the signed field cannot hold, so those commands never read one. Conflux 3.5's 4646 programs decode to their exact lengths with this layout (`tools/checks/dsa-census.ts`). The state word is read unsigned (`m_PC` is a `ui16 *`, `doc/CSBwin-src/DSA.cpp:251`) but in `LOAD`, `VARIABLESTORE`/`FETCH` and `GLOBALSTORE`/`FETCH`, which cast it to `i16`; `QUESTION`'s word is unsigned (`:859-867`).
- Every other operand word is unsigned too: `LOAD_INTEGER` (26) pushes its word as it is (`:1100-1107`), and a message's explicit delay is the word (`:663`). `LOAD` 29 (`LOAD_ABS32`) and 31 say "Illegal DSA load command" and push nothing (`:1139-1144`). A `STORE` above 25 (`:1329-1333`) and an `OVERRIDE` whose `what` is not 1 (`:1046-1059`) return before they set the next state, and the `STORE` pops nothing. `GLOBALFETCH` past the last variable pushes `0xcdcdcdcd` (`:1303-1307`). `tools/checks/dsa-decoder.ts` runs each.
- `STKOP` (`doc/CSBwin-src/Data.h:1736-1876`) has 138 values, 0 to 126 and 129 to 139. `EX_AMPERSAND` has a case for each but four: `STKOP_I_Indirect` is unpacked before the switch (`doc/CSBwin-src/DSA.cpp:2346-2392`) and then runs as the operation it carries; `STKOP_Noop` (0), `STKOP_2Dup` (23) and `STKOP_I_FilteredCast` (120) reach the default, which says "Illegal subcode in EX_AMPERSAND" and returns (`doc/CSBwin-src/DSA.cpp:4980-4982`). So 135 are operations. `STKOP_I_FilteredCast` appears only in the unpacking (`:2359`).

## Parameters

- `&NUMPARAM`, `&PARAM@` and `&PARAM!` work on the array `pDSAparameters` points at. Every filter, and the DSA `ActivateDSA` starts, runs on an array of its own whose count is 0, and the caller's is back when it returns (`NEWDSAPARAMETERS`, `doc/CSBwin-src/CSB.h:4286-4301`); the party attack's parameters are laid over the current array instead (`doc/CSBwin-src/Attack.cpp:1346-1360`). `doc/PROVEN_FACTS.md` → "A DSA filter runs on a parameter array of its own" has every site; `tools/checks/dsa-parameters.ts` runs it.

## STKOP character operations

- An index of 4 is the hand's owner, `d.HandChar`, in `&CHPOSS`, `&MASTERY`, `&CHAR@`, `&CHAR!`, `&TALENTS@` and `&TALENTS!`; in `&ISCARRIED` 4 is the hand's owner and 5 every champion (`doc/CSBwin-src/DSA.cpp:1614-1642`). An index with bit 16 set names a champion in the wings by fingerprint, in `&CHAR@` (zeros when the wings hold nobody), `&TALENTS@` (0) and `&TALENTS!` (nothing) (`:4167-4348`).
- `&PARTY@` writes `NumCharacter`, `partyLevel`, `partyX`, `partyY`, `partyFacing`, `PartySleeping`, `SeeThruWalls`, `MagicFootprintsActive`, `HandChar`, `Invisible`, `FireShield`, `SpellShield` (`:4128-4166`). `&CHAR@` writes 59: facing, food, `HP - PendingDamage` (at least 0), load, mana, ouches, charPosition, shieldStrength, stamina, water, the seven attributes as `minimum << 16 | maximum << 8 | current`, the twenty skills as (tempAdjust, experience) pairs, fingerprint, talents (`:4167-4242`). When `index + num`, unsigned, passes 100, `&PARTY@` writes nothing (`:4135`) and `&CHAR@` writes zeros from `index` up to variable 99, as it does for a champion index below 0 or past `NumCharacter` (`:4179-4184`, `:4223-4229`).
- `&CHAR!` writes back only food and water (clamped to -1023..2048), HP, mana and stamina (clamped to 0..their maximum), the attributes and the talents, and refuses the potential champion (`:4427-4542`). The HP variable is first clamped to 0..`MaxHP` in the variable itself; below `HP - PendingDamage` it sets `PendingDamage = HP - value`, otherwise `HP = value + PendingDamage`, and a champion whose `HP - PendingDamage` is not above 0 keeps both.
- `&CHPOSS` pushes -1 for an empty slot; a negative champion is the hand, a champion above 4 is 0, a slot above 29 slot 0 (`:3331-3358`). A champion slot from 0 to 3 past the party is read from the record left there: zeros at every start, so 0 (`doc/PROVEN_FACTS.md` → "A `CHARDESC` slot past the party holds zeros, or the champion who left it"). `&MASTERY`'s flags 1 and 2 are `DetermineMastery`'s 0x4000 and 0x8000, and a champion or skill out of range is 0 (`:3390-3411`).
- `&WHEREISCHAR` is the last party index with the fingerprint, else 5 when `EXPOOL` holds a 25-longword record under `EDT_Character << 24 | fingerprint`, else 4 (`:4384-4413`). `&WHOHASTALENT` sets bit `chIdx` for each champion holding every talent asked (`:4364-4383`). `&COUNTINJURY` counts the masked `ouches` bits of the living champions in the champion mask (`:4799-4819`).
- `&ISCARRIED` with an object ID pushes `256 * chIdx` plus its slot, 255 for the hand, or -1, and searches a chest's contents, which report the chest's slot; with a negative ID, a basic object type (-1 for type 0), it pushes how many are carried (`:1521-1642`).
- `&EXPERIENCE+` calls `AddToSkill` for a living champion, which adds `(UI16)(experience)` to the skill and to its basic skill (`doc/CSBwin-src/Magic.cpp:363-445`). `&CAUSEPOISON` is `PoisonCharacter` (`DSA.cpp:4349-4363`). `tools/checks/dsa-characters.ts` runs each of these.

## STKOP object operations

- `&CHARGES@`, `&CURSE@`, `&BROKEN@`, `&POISONED@` and `&SUBTYPE@` pop a slot index and push the field of the object there, 0 for an index `checkIndirectIndex` refuses or a database without the field (`doc/CSBwin-src/DSA.cpp:3412-3440`, `:3459-3484`, `:3512-3537`, `:3565-3596`, `:3630-3652`). Charges are a weapon's (`DB5` bits 10-13) and a garment's (`DB6` bits 9-12), a potion's strength (`DB8` bits 0-7) and a misc object's `value()` (`DB10` bits 14-15). A curse is a weapon's, a garment's or a misc object's bit 8; breakage a weapon's bit 14 or a garment's bit 13; poison a weapon's bit 9 alone (the garment arm is commented out); a subtype a misc object's bits 9-13 alone (`doc/CSBwin-src/CSB.h:1144-1313`).
- The five setters pop the value, then the slot, and write the same fields, cut to the field's width by `SETWBITS` (`CSB.h:749-777`); a flag is set by any non-zero value (`DSA.cpp:3441-3458`, `:3485-3511`, `:3538-3564`, `:3597-3629`, `:3653-3676`). `&CURSE!` is `SetCursed`, which brackets the bit with `AdjustStatsForItemCarried`'s -1 and +1 on the bearer, through a slot that is right only for the last champion (`doc/PROVEN_FACTS.md` → "`AdjustStatsForItemCarried`"); the port passes the right one for every champion (`DEBT.md` H). `tools/checks/dsa-objects.ts` runs each.

- `&THROW` pops the decay, damage, range, direction, launch location, object location and missile type, and is `ThrowMissile` (`doc/CSBwin-src/DSA.cpp:4559-4583`, `Timer.cpp:2016-2078`): a type whose low word is one of the eight spells `RNFireball`, `RNPoison`, `RNLightning`, `RNDispellMissile`, `RNZoSpell`, `RNPoisonBolt`, `RNPoisonCloud`, `RNMonsterDeath` flies as that spell; a type of 0 takes the first object of a database from weapon to misc in the object location's corner out of its square and throws it; any other type throws nothing. `LaunchMissile` (`Magic.cpp:17-75`) cuts the range and damage to a byte and launches on the launch location's level, with a `TT_Missile0` at `d.Time + 1`.
- `&MISSILEINFO@` pops a slot and pushes the missile's contents (its RN as a `ui16`), range, damage and direction, the last its timer's `timerWord8` bits 10-11; -1 for each when the slot is not a missile (`DSA.cpp:2796-2824`). `&MISSILEINFO!` pops the slot, and only when `checkIndirectIndex` takes it the direction, damage and range, which it writes to a missile alone (`:2825-2852`).
- `&CREATECLOUD` pops the size, the type and a location: types 0, 3, 4, 7 and 40 are `CreateCloud` of `RNFireball`, `RNDispellMissile`, `RNZoSpell`, `RNPoisonCloud` and `RNMonsterDeath` in the location's corner, with the size cast to `i16`, and 50 is `CreateFluxcage`; any other type is "Illegal cloud type" (`DSA.cpp:2741-2788`). The location is not checked.
- `&CAST` and `&FILTEREDCAST` are `DSACastSpell` (`DSA.cpp:3092-3107`, `Magic.cpp:1408-1418`): the first fourteen words of the parameters are a `SPELL_PARAMETERS`, run through `CallSpellFilter` for the second, and `CastSpell(0, …)` casts them on the party's level. `tools/checks/dsa-missiles.ts` runs these six.

## STKOP monster operations

- `&MONSTER@` pops `num`, `index` and a slot, and writes up to `num` of eight words into the variables from `index` on: `numMonM1() + 1`, the type, the four `hitPoints6`, the flags (1 `invisible()`, 2 `drawAsSize4()`, 4 `Unique()`, 8 `Poisoned()`) and `alternateGraphics()`; a slot that is no group gives zeros and -1 for the type (`doc/CSBwin-src/DSA.cpp:3993-4057`). The four flag getters are gated on the design options (`CSB.h:1128-1135`), so on a dungeon without them the flags read 0.
- `&MONSTER!` pops the same three and writes back, from those variables, the hit points for `i < 4` and `i < num - 2`, then the four flag bits if `num > 6` and the graphics if `num > 7` (`DSA.cpp:4076-4127`). The setters are not gated. `num` is a `ui32`, so a `num` of 0 or 1 writes all four hit points.
- `&MONPOSS` pops a possession index and a slot, and pushes the slot of that possession of the group, counted from 0, or -1 past the last (`DSA.cpp:3359-3389`). For a slot that is no group it pushes 0xffff, the integer of the default `RN` (`CSBTypes.h:306`, `:377`).
- `&DELMON` pops an index and a location, and is `DeleteMonsterInGroup` (`DSA.cpp:1742-1749`, `Monster.cpp:4613-4752`): the member leaves, and the group closes up over it as for a death in `DamageMonster`, the `TT_MONSTER` timers renumbered in fear 6, but with no remains, cloud or delete filter. A group of one, or an index past the last member, is left alone. `&INSMON` pops a corner mask and a location, and is `InsertMonsterInGroup` (`DSA.cpp:1751-1758`, `Monster.cpp:4755-4833`): a group of horizontal size 0 takes up to four, in corners of the mask's low four bits, and of size 1 up to two, in corners 0 and 2; a copy of member 0 goes into the first free corner, with its hit points, a copy of the first `TT_MONSTER_A0` or `TT_MONSTER_B0` the timer walk meets renumbered to the new member, and the facing byte rebuilt from the record's `facing()` alone. Both run `NOFILTER`.
- `&MONBLK` pops a mask and sets `monsterMoveInhibit[0..3]`, north to west, to its bits 1, 2, 4 and 8 (`DSA.cpp:4626-4639`), which `PossibleMove` refuses (`Monster.cpp:675`). `ProcessTimers29to41` clears them before it runs the monster move filter (`:3314-3317`), so only that filter's `&MONBLK` is ever read.
- `&MONL&D` does nothing, and pops nothing, unless `monsterMoveFilterActive`, which `ProcessDSAFilter` sets only while the monster move filter runs (`DSA.cpp:4776`, `:5316-5327`). Then it pops an index, does nothing more past 98, and writes `1024 * level + 32 * x + y` of the group, from parameters 0 to 2, and its distance to the party from parameters 5 and 6, less one, into that variable and the next (`:4769-4791`). `tools/checks/dsa-monsters.ts` runs these seven.

## STKOP text operations

- A run's `DSADBANK` holds ten texts, `textStrings`, none until the first is set (`doc/CSBwin-src/DSA.cpp:125-150`, `:195-213`). `SetText` ignores an index past 9; `GetText` gives "" while none is set or for one never set, and does not check its index.
- `&TEXT@` pops a text index and an object index: past 9, an index `checkIndirectIndex` refuses (0, or at or past `dataMapLength`) or an object that is no text, it does nothing; otherwise the text is `DecodeText(…, 0x8002, 999)`, forced visible, its separators linefeeds (`DSA.cpp:3169-3194`). `&TEXTSAY` pops a colour and an index and prints that text through `PrintWithSubstitution` (`:3240-3253`).
- `&CHARNAME@` pops an index and a fingerprint, both as words, and sets that text to the name of the first champion with the fingerprint, then of a champion in the wings (`LocateInWings`), or "" (`DSA.cpp:3205-3238`). `SetText(pName, 8, index)` copies nine bytes from the name.
- `&GLOBALTEXT!` pops a global index and a local one, and is `SetGlobalText(GetText(local), global)` (`DSA.cpp:3195-3203`): the text, cut to 99 bytes, and its zero become the `EXPOOL` record `(EDT_GlobalText << 24) | (index & 0xffff)` of `(len + 4) / 4` longwords, its bytes in memory order, the bytes past the zero from an uninitialised buffer (`CSBCode.cpp:5360-5372`). `expool.Write` puts it ahead of any earlier record with that key, which stays. `DecodeText`'s `.R.` reads it (`SubstituteGlobalText`, `:5374-5398`), as does the action name filter (`:8805-8816`).
- `&SAY` pops a colour and a location; for a valid location it decodes the first text object of the square, at any corner, as `&TEXT@` does, and prints it through `PrintWithSubstitution` (`DSA.cpp:3138-3161`). `&DISCARDTEXT` is `scrollingText.DiscardText()` (`:3162-3168`).
- `PrintWithSubstitution` (`Graphics.cpp:1564-1620`) queues the text as one print-queue entry, a linefeed first, and nothing if the text is empty. `@p` is the name of champion `d.AttackingCharacterOrdinal - 1`, `@N` a linefeed, and any other `@x` "HUH???" and `NotImplemented`; each is preceded by a space unless the output ends in a linefeed, and followed by one. The replacement is the pointer `p_4`, initialised to "HUH???", which each escape copies to its end: so `@N` copies what is left of it, "HUH???" before any other escape and nothing after one. `tools/checks/dsa-text.ts` runs these six and this function.

## STKOP message and sound operations

- `&MESSAGE` pops a delay, a parameter count, a message type and a location, in that order, and does nothing more past 29 parameters (`doc/CSBwin-src/DSA.cpp:3046-3072`). An `Override_P` replaces the location's corner. It sets a `TT_ParameterMessage` (101) timer due at `d.Time + delay` on the location's level: `uByte5` the low byte of `parameterMessageSequence++`, `uByte6`/`uByte7`/`uByte8` the square and corner, `uByte9` the message type. The first `numParam` DSA parameters go into `EXPOOL` under `(EDT_MessageParameters << 24) + timerID`, `timerID` being what `SetTimer` returns (`:3073-3089`).
- `parameterMessageSequence` goes back to 0 at every `d.Time++`, in the main loop (`CSBCode.cpp:686`) and in `_ProcessTimersViewportAndSound` (`Attack.cpp:2212`), and at a load (`SaveGame.cpp:1749`). At the same time, a parameter message runs before any other timer, and two of them by the lower `uByte5` (`TIMER::operator<`, `Timer.cpp:779-791`).
- `ProcessTimers` sends a parameter message to `ProcessTT_OPENROOM`, or to `ProcessTT_STONEROOM` when the target is a wall (`CSBCode.cpp:6504-6517`). Both, and `ProcessTT_FALSEWALL`, begin by setting the DSA parameters: for a parameter message, `pDSAparameters[0]` is `expool.Read` of its record, which leaves the pool, -1 when there is none, and the words follow; for any other timer the count is 0 and the words stay (`Timer.cpp:1399-1407`, `:1699-1707`, `:2178-2186`). `ProcessTT_STONEROOM` then makes the timer a `TT_STONEROOM`; `ProcessTT_OPENROOM` keeps the function, so the message reaches only the square's DSAs (`:1715-1716`, `:1760-1761`).
- The `I_` operations are `Indirect` (`doc/CSBwin-src/DSA.cpp:2094-2193`, the cases `:4958-4972`): in a dungeon with no `EDT_SpecialLocations` record for `ESL_INDIRECTACTIONS` (5) it does nothing, not even pop (`:2110-2121`). Otherwise it pops `numVar` values into a record `[type, numVar, the values in popping order, array, …, numParam, the first numParam DSA parameters]`. `&%MONSTER!`, `&%CHAR!` and `&%CELL!` are arrays: the first value popped is a count, nothing is sent past 20, and the variables from the second value on follow the flag. The counts: `&%DEL`, `&%DELMON`, `&%INSMON`, `&%CAUSEPOISON`, `&%COPY` and `&%SWAPCHARACTER` 2, `&%ADD`, `&%CREATECLOUD` and the three arrays 3, `&%TELEPORTPARTY` 1, `&%MOVE` 10, `&%THROW` 7, and `&%CAST` none but 13 parameters. A record of more than 29 words is sent nowhere. It goes into `EXPOOL` as a `&MESSAGE` record does, under a `TT_ParameterMessage` timer to the location's level and square, corner 0 and message type 0 (`uByte8`, `uByte9`), with the next `parameterMessageSequence`, due at `d.Time`, or `IndirectActionDelay` ticks later when that is above 0, which then goes back to -1 (`:2175-2192`). `&%DELAY` pops `IndirectActionDelay` (`:4973-4979`), which every DSA run starts at -1 (`:5356`). CSBWin looks the location up once a process (`indirectLocChecked`, a function `static`, `:2098`).
- `&%INDIRECT` (`DSA.cpp:2346-2392`) reads the record its DSA was sent: a first word that is no `I_` operation, `STKOP_I_FilteredCast` included, ends it; otherwise the values go back on the stack in their old order, an array's variables back from the index it names, and the record's parameters to the front of the DSA parameters, whose count stays the record's length. The operation then runs as its plain form (`&DEL` for `&%DEL`, …). `tools/checks/dsa-indirect.ts` runs both.
- `&SOUND` pops flags, a volume and a number, and is `PlayCustomSound` (`DSA.cpp:4613-4625`, `Sound.cpp:1048-1069`). A negative number `n` is `d.sound1772[-n - 1]`, nothing past the 22nd, played by `StartSound`: loud, attenuated 18 times for a volume of 0. A number from 0 up is a `CGT_Sound` of `CSBgraphics.dat` (`SOUNDDATA::ReadSound`, `:998-1034`), played through `SOUNDDATA::Decode` with the volume as the samples' divisor, 1 for a volume of 0 (`doc/PROVEN_FACTS.md` → "`CSBgraphics.dat`'s sounds are WAV files, each byte stored as the change from the one before"); without one, it plays nothing, the first time with "Cannot find Sound". The flags are not used. `tools/checks/dsa-message.ts` runs these two, and `tools/checks/custom-sounds.ts` the sounds of both `CSBgraphics.dat` here.

## STKOP dungeon and program operations

- `&LOC2ABSCOORD` pops a location and pushes its level, its column and row plus the level's `offsetX` and `offsetY`, and its corner (`doc/CSBwin-src/DSA.cpp:3254-3270`, `LOCATIONABS::operator =`, `:321-328`).
- `&ECF@` pops a location and pushes its eight extended cell flags, flag `i` in bit `i`. They are bit `y` of the eight longwords of the `EXPOOL` record `(EDT_ExtendedCellFlags << 24) | (l << 5) | x`, one record a column; without a record of eight, 0 (`DSA.cpp:3271-3298`). `&ECF!` pops a location and flags, takes that record out with `expool.Read`, zeroed when missing or short, sets the cell's bits from the low eight of the flags, and writes it back (`:3299-3328`). `ECF_FOOTPRINTS` (0) is the one flag CSBWin reads, in `SummarizeRoomInfo` (`Codea59a.cpp:419-425`, `GetExtendedCellFlag`, `data.cpp:1682-1692`), where it shows footprints on the cell once `d.Time > 0` (`doc/PROVEN_FACTS.md` → "YA BRO ROS marks the trail from the cast onwards").
- `&MULTIPLIER@` pops a level and pushes its `experienceMultiplier()`, `word12` bits 12-15, or 1 when the level is not below `NumLevel()` (`DSA.cpp:3975-3991`).
- `&PARTYDISTANCE` pops a location and pushes `|dx| + |dy|` to the party on its level, and `-|dl|` otherwise (`DSA.cpp:4058-4074`).
- `&J*` pops a state, then a column, into the packet's `m_transferState` and `m_transferCol`, as `JUMP` does (`DSA.cpp:4738-4746`). `&G*` pops a state, then a column, and calls `Execute` on the master DSA as `GOSUB` does, one subroutine level down (`:4747-4768`).
- `&THISDSAID` pushes the slave's `RN` as an integer (`DSA.cpp:4823-4829`). `&DSAINFO@` pops an object, and pushes the selector, the state bits, `ParameterA()` and `ParameterB()` of a type-47 actuator, or four -1 for anything else (`:2440-2471`).
- `&BITCOUNT` pushes the set bits of the 32 popped (`DSA.cpp:4833-4850`).
- `&VSET` pops `n`, `dst` and `src`, and does nothing for a `dst` past 99, unsigned. Otherwise the `n` variables from `dst`, cut at 99, are set to `-src` for a negative `src`, to `src - 100` for one past 99, both made well defined, or else copied by `memmove` from those at `src`, cut at 99 again, with their states (`DSA.cpp:4851-4898`).
- `&THISCELL` and `&NEIGHBORS` pop a criteria mask and a location, and are `ExamineCell` of the cell itself, or of its four neighbours from north clockwise, a result bit each (`DSA.cpp:2211-2321`, `:4820-4832`). A cell's bits say what it is, from its cell flag `cf`: 0 off the map, 1 stone, 19 open; a pit 4 when false (`cf & 1`), else 2 when open (`cf & 8`), else 3; a door 5 plus its state `cf & 7`, 9 past 5; a teleporter, when its square has one, 11, 15, 13 or 17 for its `what()`, plus 1 when `cf & 8` is clear; a false wall 22 for `cf & 4`, else 20 for `cf & 1`, else 21; stairs 23 for `cf & 4`, else 24. Bits 29 to 31 say what is on it: the party, else a monster, else nothing, and off the map and stone are nothing. The cell's bit is set when the mask shares one bit with each half. `tools/checks/dsa-dungeon.ts` runs these thirteen.

## Timers and selector resolution

- `ProcessDSATimer6` resolves the slave DSA by mapping `DB3::DSAselector()` through `DSALevelIndex[level][selector]`, computes `inputMsgType = 3 * timerPosition + timerTypeModifier[timerUByte9]`, executes the DSA, and writes the resulting state back via `GetState`/`PutState` (`doc/CSBwin-src/DSA.cpp`).
- CSBWin implements no slave DSA. `FindMaster` returns the DSA's own actuator as its master when `IsMaster()`, that is when `LocalState()` is not 3 (`doc/CSBwin-src/Data.h:2479-2482`); for a local state of 3 it warns "Slave DSA Not Implemented" and returns the slave all the same, leaving the master's x and y unset (`doc/CSBwin-src/DSA.cpp:535-548`), and `GetState` and `PutState` then find local state 3 illegal (`:550-572`). No dungeon here has such a DSA: Conflux 3.5's local states are 0 and 1, and 3D2D1D's are 0.
- A run's next state is that of its first command, not its last: `DSA::Execute` keeps the first `m_nextState` that is not negative (`doc/CSBwin-src/DSA.cpp:5274-5283`), and every command sets one from its own relative-state field. A program that changes its DSA's state does it in its first word, a `NOOP` with the change (`EX_NOOP`, `:575-592`).
- A selector mapped to 255 names no DSA. In a wall, the type 47 actuator is a wall decoration of `CSBgraphics.dat` (`doc/CSBWIN_DECORATIONS_REFERENCE.md` → "A wall decoration of `CSBgraphics.dat`"); a timer that reaches it says "Undefined Master DSA" and runs nothing (`DSA.cpp:5395-5410`).
- `QueueDSASwitchAction` maps target room type via `Byte1596` and queues `TT_DESSAGE` when `MorD != 'M'`; non-stone/falsewall targets force `targetPos = 0` (`doc/CSBwin-src/DSA.cpp`).

## STKOP cell operations

- `STKOP_CellFetch` packs room data into a variable array: slot 0 is `roomType`, slot 1 encodes room attributes (room-type specific), and slot 2+ contain teleporter facing/what/dest or door state/type/decoration when present (`doc/CSBwin-src/DSA.cpp:3677-3837`).
- `STKOP_CellStore` writes room attributes back to `CELLFLAG` and updates teleporter/door fields (rotation, scope, door switch/mode, etc.) with guard rules for door state transitions (bashed/open) (`doc/CSBwin-src/DSA.cpp:3838-3958`).
- `STKOP_GetSkin` and `STKOP_SetSkin` read and set a cell's skin through `skinCache` (`DSA.cpp:3108-3136`); see `doc/CSBWIN_RENDERING_REFERENCE.md` → "Skin cache".
- `STKOP_FalsePit` toggles bit 0 on pit `CELLFLAG` when the location is valid and room type is PIT (`doc/CSBwin-src/DSA.cpp:2860-2876`).

## Generator delay helpers

- `STKOP_GeneratorDelayStore` locates the first monster generator (type 6) in an open room and writes its disable time (falling back to a disabled type 0 actuator if present); `STKOP_GeneratorDelayFetch` reads the disable time for the first type 6 generator (`doc/CSBwin-src/DSA.cpp:2877-2916`, `:4725-4737`).

## EX_ADD and EX_DEL

- `EX_ADD` validates negative destinations (`-1` cursor empty, `-100..-999` character slot empty, `<= -1000` monster RN = `-location/1000`) and positive destinations by bounds only, clones the object via `CopyItem`, sets `mostRecentInterestingObjectID` to the new RN, and for cell placement chooses a random position from `posMask` bits before calling `MoveObject(newObj, -1, 0, x, y)` and setting `newObj.pos(p)` (`doc/CSBwin-src/DSA.cpp:1967-2091`).
- `EX_DEL` ignores `objID` for negative locations (cursor/character slot), but for positive locations it removes only the matching RN and only for `dbACTUATOR`, `dbMISC`, `dbPOTION`, `dbWEAPON`, or `dbCLOTHING`, then queues DB deletion (and deletes scroll text records separately) (`doc/CSBwin-src/DSA.cpp:1645-1739`).

## DSA MoveObject restrictions

- DSA `MoveObject` uses source/destination types `{1=cell,2=cursor,3=monster,4=character,5=chest}`, validates source first (positive error codes) and destination second (negative error codes), enforces `dstDepth == 0` for cell/chest/monster, blocks clouds, checks chest ownership (character possession), limits chest contents to 8 items, and validates character slots using `ObjDesc[descIndex].word4` vs `CarryLocation[slot]` (`CheckSource` and `CheckDestination`, `doc/CSBwin-src/MoveObject.cpp:369`, `:674`, and the `Find…Source` and `Find…Destination` they call, `:130-673`).
